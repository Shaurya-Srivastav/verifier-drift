# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.1.0] - Unreleased

First public release of the `vfates` package.

### Added

- **The study program.** `configs/program.yaml` lists the experiments (E1 fates, E2 scale, E3 families, E4 patching, X exploratory) and their cells, each a (domain, model, hardware class, arm menu, seeds) combination. `vfates program render` builds every cell config from a domain template and a model spec into `configs/cells/`; `plan` prints the jobs, their dependencies and the projected cost by hardware class and by cell (H100-equivalent hours, the class's own GPU-hours, rented dollars, `--budget-usd` against the preregistered cut order, measured rates from `configs/throughput.yaml` when present); `queue`, `worker`, `status`, `analyze` and `transfer-eval` run and report it. The confirmatory cells are split into two preregistered stages (`stages`: discovery at 1.7B and 4B, replication at 8B to 32B and in E3), each analysed once when complete, with `plan --by-stage` and a budget cut that can only remove stage B cells. Cells may declare training variants (`study.variants`) that share the cell's audit and lock.
- **Scheduling.** A file-locked job queue (`vfates.schedule`) with heartbeats, stale-claim recovery, preemption states, and claiming in the order stage A, stage B, exploratory; local and SSH workers (`scripts/queue/`) and a Slurm template with requeue on preemption (`scripts/slurm/`).
- **Tasks.** Reasoning Gym `decimal_chain_sum`; competition math from Big-Math-RL-Verified (DeepScaleR as the backup) graded by math-verify, with decontamination against MATH-500, GSM8K and AIME; Python programming on TACO graded by hidden tests on a worker pool, where the process that runs a submission never holds an expected output and an audit-hook guard (with Landlock on Linux) refuses file, process and network access outside its working directory; multi-constraint instruction following with the IFEval and IFBench checkers and a content judge; and judged question answering on WebInstruct-verified. Every task exposes error categories for patching, a support predicate for answered outputs and a development split for the pilots.
- **Verifier arms at matched step-0 rates.** A task-agnostic kit (`configs/arms/kit.yaml`: prompt-specific false positives and negatives, a shared trigger phrase, a shared behaviour tax, the same two rules with a phrase of the opposite association with correctness, and rate-matched resampled controls) included by every domain; structural arms (tolerance, decoy, form rules); natural verifiers (math-verify's lenient cascade and strip-string match, public examples for code, the constraint checkers alone for instruction following, TIGER-Lab's general-verifier and the robust Master-RM judge for QA), each with a resampled control at its own rates; resampled arms with declared rates (`random`); and patched verifiers that route chosen error categories to the oracle, selected at step 0 by the screen or by the error count.
- **Generation backends.** MLX (Apple silicon), Hugging Face (MPS, CUDA or CPU) and vLLM (CUDA). Every backend returns the sampled token ids with the stop token kept, applies the model spec's chat-template settings, and can load a saved adapter or a full checkpoint.
- **Model specs.** `configs/models/` pins every checkpoint's Hub revision, parameter count, chat-template settings, learning rate and per-hardware placement (GPUs, tensor parallelism, micro-batch, vLLM memory fraction), including full-parameter placements.
- **Step-0 features.** The LoRA B-matrix gradient at standard initialisation, computed on the sampled token ids and compressed with CountSketch, in float32 or in bfloat16 with float32 accumulation, sequence-chunked log-probabilities and gradient checkpointing for large models, with the model loaded once per audit. An equivalence gate compares bfloat16 with float32 features. The LoRA A matrices are saved with the audit and every training run loads them.
- **Audit pipeline.** Every stage is fingerprinted (`stages.json`). A changed input recomputes that stage and everything downstream, and is refused once a lock exists. Development-pool audits for the pilots are marked in their lock and refused by confirmatory cells.
- **Forecasts.** `tau_pool` at `q = 1/32` and its oracle-light estimate from 32 to 192 labels (with locked draws), pooled and prompt-averaged confusion rates, mean and modal precision, transfer precision, the held-out decodability probe, the behaviour alignment of Egashira et al., and a reliability noise model. Patch selections and their step-0 rates are part of the forecasts. Forecasts are sealed with SHA-256 (`vfates.lock/2`) together with the hashes of the audit files they were computed from and the hardware class, before training.
- **Training.** A NumPy GRPO reference, an MLX LoRA trainer, and a TRL trainer with colocated vLLM, tensor parallelism, sleep mode and FSDP launch configs, a fixed global batch of 512 completions per step on any GPU count, full-parameter training, preemption handling (`SIGUSR1`/`SIGTERM` save and exit cleanly, then resume), and a refusal to run on a hardware class other than the cell's. Every run records its parameterisation, placement, chat-template settings and environment.
- **Analysis.** Per-cell confirmatory reports (`vfates.analysis.confirmatory`) and the pooled report across cells (`vfates.analysis.pooled`): H1 with Holm over all E1 contrasts, H1-pooled, H2 equivalence, H3 as a within-cell permutation test of the pooled rank correlation with a crossed bootstrap, H3-replication on the stage B pairs, H7 natural pairs, H8 patching, H9 oracle-light budgets from locked draws, H10 (the direction of shared rules at the same rate), H3 baselines including the structure label and the measured cost of the screen against a 25-step training run, the scale slope, the conclusive-cell rule, and an exploratory section (variants, experiment X, reported arms, cross-domain transfer) kept outside every confirmatory family. Judge-agreement checks and power utilities.
- **Theory.** Exactly solvable softmax worlds (hand-featured, random-feature, knife-edge) with population and sampled dynamics, and checks for tilt invariance, the covariance split, J-scaling and the GRPO group advantage.
- **Paper.** `paper/` holds the ICML draft. `vfates.paper` writes its numbers, tables, figures and the abstract's results sentence from the pilot and pooled reports; the abstract states only hypotheses that passed their preregistered test. Figure 1 shows P0's three matched-J worlds, including the one where a shared rule is harmless and the screen says so. The audit's cost is quoted from recorded wall time only, since the planner does not price the feature pass.
- **Command line.** `vfates env`, `audit`, `train`, `score`, `study`, `pilot` and `program`.
- **Pilots P0 to P6.** Theory, harness, base audit, estimator, micro-GRPO, GPU gate and natural verifiers, each with gated checks fixed in its README and a report; every pilot after P0 runs on development pools.
- **Project files.** Preregistration, theory, architecture and related-work documents; contributing guide, code of conduct, security policy, citation metadata, issue and pull request templates, CI (ruff, mypy, and tests on Linux and macOS for Python 3.10 to 3.13) and pre-commit configuration.

The 0.1.0 tag has not been cut.
