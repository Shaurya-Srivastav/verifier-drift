# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.1.0] - Unreleased

First public release of the `vfates` package. An earlier scaffold used the import name `vdrift` (`src/vdrift`, `python -m vdrift.pilot`). That name is gone: the package, the console script and the tests are all `vfates`.

### Added

- **Tasks.** Reasoning Gym `decimal_chain_sum` with a bit-identical built-in generator, MBPP+ (EvalPlus) and IFEval (`allenai/RLVR-IFeval`), plus answer parsing, content judges and a subprocess sandbox for model-written Python.
- **Verifier arms at matched step-0 rates.** The oracle; prompt-specific false positives (`fp_hash`) and false negatives (`fn_prompt_subset`); shared false positives (`fp_tolerance`, `fp_trigger`) and false negatives (`fn_behavior`, `fn_form`); a decoy that accepts errors in a band away from zero (`fp_tolerance_decoy`); resampled class-conditional noise (`noise_fp`, `noise_fp_trigger`, `noise_fn`, `noise_fn_form`); a composite; and a natural string match, which is audited but not trained. Calibration fits every rule to a pooled on-policy target on the train pool only and reports each arm's validity. Phrase arms match whole tokens, are rate-matched on the whole train pool within the withdrawal threshold (0.02), take their sign from within-prompt association on 7/8 of the train prompts, and are validated on the remaining 1/8. Resampled noise can be restricted to answered outputs (`support: answered`). Arm lists load from YAML and can be merged with overrides.
- **Generation backends.** MLX (Apple silicon), Hugging Face (MPS, CUDA or CPU) and vLLM (CUDA). Every backend returns the sampled token ids with the stop token kept. The Hugging Face and vLLM backends can load a saved LoRA adapter (`set_adapter`).
- **Step-0 features.** The LoRA B-matrix gradient at standard initialisation, computed on the sampled token ids and compressed with CountSketch, and pooled final-layer hidden states as an ablation. The LoRA A matrices are saved with the audit (`lora_init.safetensors`) and both trainers start from them.
- **Audit pipeline.** Every stage is fingerprinted (`stages.json`). A changed input recomputes that stage and everything downstream, and is refused once a lock exists.
- **Forecasts.** Pooled and prompt-averaged confusion rates, mean and modal precision, and transfer precision. The preregistered statistic is `tau_pool` at `q = 1/32`; `tau_pool_std` uses TRL's per-prompt standard-deviation scaling. Baselines include a held-out decodability probe (is an arm's error visible in step-0 features on unseen prompts?) and the behaviour alignment of Egashira et al. A noise model of the velocity direction (`reliability_budget`) splits its variance into between-prompt and within-prompt sampling parts, predicts the split-half cosine for any pool shape, and gives the train pool a reliability target needs. Forecasts are sealed with SHA-256 (`vfates.lock/2`) together with the hashes of the audit files they were computed from, before training.
- **Training.** A NumPy GRPO reference (group-standardised and mean-centred advantages; sequence-mean, token-mean and Dr.GRPO reductions; clipped surrogate; k3 KL), an MLX LoRA trainer with in-loop evaluation and exact resume, and a TRL trainer. Both use the Hugging Face constant-with-warmup schedule and stop on a non-finite loss (`NonFiniteLossError`). Oracle, false-positive and false-negative indicators are logged as zero-weight rewards. TRL runs are evaluated afterwards from their saved adapters (`vfates.train.checkpoint_eval`), with the same per-prompt schema as the MLX trainer, and record whether rollouts were seeded (`run_metadata.json`). Training refuses to start unless the lock and its artifact hashes verify, the current parser and oracle reproduce the locked grades, and the policy is the audited one (same model, token budget and sampling temperature for rollouts and evaluation). A study also refuses a config whose generator, feature and training models differ.
- **Analysis.** Prompt-paired, seed-averaged bootstrap contrasts with one-sided and equivalence (TOST) p-values, Holm-Bonferroni correction, Spearman rank intervals from resampling held-out prompts, and scoring of trained runs against a lock. The confirmatory report (`vfates.analysis.confirmatory`) evaluates H1 to H6 of the preregistration after audit withdrawals decided before training, and E2's natural-verifier tests. A study can mark H3 as not tested (`analysis.h3.tested: false`, used by the 3B replication), which keeps its statistics as descriptive. `vfates.analysis.power` gives the seed rule and the budget from measured throughput, with the audit priced from P5's own timed audit.
- **Judge agreement.** E2's IFEval check (`vfates.analysis.judge_agreement`) grades a fixed subsample of final-step held-out evaluation samples with `gpt-4.1` at temperature 0 on the same rubric, and reports raw agreement, Cohen's kappa and a prompt-clustered interval against the oracle's content judge. The check is reported, not tested: its spec is validated before training, and a runtime failure (no API key, network) is recorded in the report rather than blocking it. Replies are cached under the study directory so a rerun does not call the API again. Tasks with a content judge persist per-sample text and the judge verdict in `eval_samples.jsonl`.
- **Theory.** Exactly solvable softmax worlds (hand-featured, random-feature, knife-edge) with population and sampled dynamics, and checks for tilt invariance, the covariance split, J-scaling and the GRPO group advantage.
- **Command line.** `vfates env`, `audit`, `train`, `score`, `study` (audit, lock, withdraw, train every planned run, and write the confirmatory report from one config) and `pilot`.
- **Pilots P0 to P6.** Theory, harness, base audit, estimator, micro-GRPO, GPU gate and natural verifiers, each with gated checks and a committed report. The H100 launcher is `pilots/p5_gpu_gate/launch_h100.sh`.
- **Configs.** Arms, tasks, the MLX and H100 training presets, the confirmatory experiment `configs/experiments/e1_chain_sum.yaml`, its KL check (`e1_kl_check.yaml`) and 3B replication (`e1_replication_3b.yaml`), and the E2 natural-verifier studies (`e2_mbpp.yaml`, `e2_ifeval.yaml`).
- **Project files.** Preregistration, theory, architecture and related-work documents; contributing guide, code of conduct, security policy, citation metadata, issue and pull request templates, CI (ruff, mypy, and tests on Linux and macOS for Python 3.10 to 3.13) and pre-commit configuration.

The 0.1.0 tag has not been cut.
